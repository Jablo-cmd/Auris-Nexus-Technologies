# Auris Nexus Technologies: SEO and AI Search Visibility Audit

**Audit date:** 30 October 2026
**Scope:** repository `Jablo-cmd/Auris-Nexus-Technologies` and the live site https://aurisnexus.co.za
**Live vs repository:** the live site is served by GitHub Pages from this repository. The live `robots.txt` and `sitemap.xml` were byte-identical to the repository at audit time.

No result in this document is a guarantee of rankings or AI recommendations. The goal is to make the site accurate, crawlable and easy to understand; visibility then depends on external authority, competition and each platform's own systems.

### 1. Existing strengths

- Unique titles, meta descriptions, canonicals, Open Graph and Twitter tags on every indexable page; the existing QA script reports 0 errors and 0 warnings.
- A single, consistent organisation entity (`#organization`) in JSON-LD on every page, with legal name, CIPC number, address, phone, email and LinkedIn.
- FAQ schema is generated from the visible FAQ markup, so schema and on-page content cannot drift apart.
- NAP (name, address, phone) is consistent across the site: 140 Linden Street, Sandown, Sandton 2196; 063 122 6552; info@aurisnexus.co.za. No old addresses or alternative numbers were found.
- Case studies show an honest status label (Delivered, Deployed & In Use, In active development, Built & Tested, Completed).
- The Insights section has a named author page, an editorial policy and Article schema.
- Responsive images (WebP with 640px variants), preloaded self-hosted fonts and explicit image dimensions.

### 3. Missing SEO elements (before this work)

- No explicit rules for AI search crawlers in `robots.txt` (everything was allowed via `*`, so nothing was blocked, but the policy was implicit).
- No dedicated page for two of the five core service pillars: **Custom Software Development** and **Digital Transformation**.
- The organisation schema did not link to its core services and did not include the tagline.
- No `llms.txt`.

### 4. AI discoverability weaknesses

- Positioning drift: the Solutions menu led with Web Development and Web Design, and the site has four city web-design pages (Johannesburg, Pretoria, Cape Town, Durban). That pulls the entity towards "web design agency", against the intended positioning. The city pages are not duplicates of each other (pairwise text similarity 18–43%) but they are short (about 530–610 words).
- AI answer engines rely heavily on third-party corroboration (directories, LinkedIn, press, reviews on platforms). The site cannot supply this alone; see section F and `docs/GROWTH_AUTHORITY_AND_ANALYTICS_PLAYBOOK.md`.
- Case studies do not state whether each project was a commercial client engagement or an internal product, and none lists its technology stack.

### 5. Content gaps

- No pillar pages for Custom Software Development and Digital Transformation (fixed, see B).
- Of the 10 requested Insights topics, 5 already have close coverage; 5 were missing (drafts prepared, see C).
- No "Auris AI" project exists anywhere in the repository. No case study was created for it.
- The case studies have no technology-stack section.

### Crawler configuration

Based on current vendor documentation (checked 30 October 2026):
- **OAI-SearchBot** controls whether pages can appear in ChatGPT search. **GPTBot** controls use for model training. They are independent: a site can allow one and block the other.
- **ChatGPT-User** and **Perplexity-User** fetch pages when a user asks for them; the vendors say robots.txt may not apply, so they are not listed.
- **PerplexityBot** builds Perplexity's search index and, per Perplexity, is not used for foundation-model training.
- **Google-Extended** controls Gemini/Vertex AI training use and does not affect Google Search or AI Overviews eligibility (those use Googlebot).

Sources: [OpenAI crawlers](https://developers.openai.com/api/docs/bots), [Perplexity crawlers](https://docs.perplexity.ai/docs/resources/perplexity-crawlers.md).

**Robots policy (owner decision):** training crawlers are currently allowed, matching the previous `Allow: /` for everyone. If the company prefers not to contribute content to model training, change `Allow` to `Disallow` under GPTBot, Google-Extended, ClaudeBot and Applebot-Extended. Search visibility is unaffected by that change.

### Performance

No regressions introduced: new pages reuse existing CSS and JS, existing responsive WebP images with `srcset`, explicit dimensions, and one eager hero image with `fetchpriority="high"`. Core Web Vitals field data requires Search Console / CrUX access (see D).
